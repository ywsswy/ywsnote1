## 操作系统的「按需分页 / demand paging」机制：
- mmap只登记虚拟内存，不分配物理页，实际读取时触发page fault（缺页）时才分配物理内存
- new 出来的是VIRT虚拟内存，memset之后才会变成RES常驻内存，
- std::vector的大数据reserve，也是只分配虚拟内存，不分配物理内存，实际push_back时触发缺页时才分配物理内存；pop_back后并不会释放物理内存；（必须要用户调用shrink_to_fit才会释放物理内存）（已通过top观察验证）
- std::vector设计上每个元素只是虚拟内存地址连续（用户态感知到的），但是物理地址不一定连续；写满扩容瞬时，物理内存会变2倍（1原+1新），虚拟内存会变3倍（1+1x2），然后物理内存回落到原大小，虚拟内存会回落到2倍；
- 按需分页的好处：（1）避免物理内存浪费；（2）fork时高效节约，不用触发实际物理内存的拷贝；（3）读大文件的某一小块时可以用mmap省物理内存（加载也快吧？）；

- 虚拟内存上限：受限于cpu架构，32位cpu最多4GB空间（也就是4GB个字节），当前主流x86_64也没用满64位，就能放256TB空间；
- 物理内存上限：min（CPU 理论上限，主板上限，实际插内存条的容量），往往都是受限于内存条。。
- swap（交换空间）：适用于物理内存不够时可以跟放一部分到磁盘，如果不开swap内存不够就会oom-killer，但是性能问题一般不开swap；
- 进程间的虚拟内存地址各自独立；但物理内存是共用的；

- cache miss不同于缺页，前者是不同缓存层级之间的切换（例如L1/L2/L3没有，从主存RAM中读取），后者是物理内存和虚拟内存之间的切换；不管是缺页还是cache miss都可以通过perf state工具统计
